DNS Zone Transfer Vulnerability
------------------------------->>
1. Find the DNS Nameservers for the Target
> dig ns target.com
        or 
> host -t ns target.com
 

Sample Output:
target.com.    3600    IN    NS    nstm1.digi.ninja.
target.com.    3600    IN    NS    nstm2.digi.ninja.

2. Attempt a Zone Transfer
> dig @nstm1.digi.ninja target.com axfr (If successful, this will dump all DNS records for the domain. If not, it will show Transfer failed.)
 { dig @nstm1.digi.ninja axfr target.com}

## Repeat with other nameservers if necessary:
> dig @nstm2.digi.ninja target.com axfr


3. (Optional) Use host for Zone Transfer
> host -l target.com nstm1.digi.ninja


✅ Successful Zone Transfer

sub1.target.com has address 192.168.1.10

========================================
SSRF (Server-Side Request Forgery) Notes
========================================

----------------------------------------
   I. SSRF Classification Framework
----------------------------------------
1. Reflected SSRF
   - Server fetches external URL and returns response.

2. Blind SSRF
   - No visible response.
   - Confirm via out-of-band interaction (DNS/HTTP).

3. Semi-Blind SSRF
   - Timing differences
   - Error message variations
   - Response code changes

========================================

Key Areas to Hunt for SSRF
----------------------------------------
1. Image upload (PNG → SVG conversion)
2. Video upload processing
3. Open Redirect chaining
4. JavaScript-based URL fetch
5. Profile update fields (website, avatar, bio link)
6. Contact forms
7. Register forms (name, address, website fields)
8. HTML-to-PDF conversion
9. XML-RPC endpoints
10. Chatbot URL fetching features

----------------------------------------
Common SSRF Injection Points
----------------------------------------
- Insert URL fields
- Add website field
- Add profile link
- Upload image (external fetch)
- Upload video (FFMPEG processing)
- Webhook URL
- Verify URL field
- Redirect parameters
- Proxy features

----------------------------------------
Basic Manual Testing Workflow
----------------------------------------
1. Intercept request in Burp Suite before submission.
2. Look for parameters that accept URLs.
3. Replace parameter value with Burp Collaborator URL.
4. Submit request.
5. Monitor Burp Collaborator for DNS/HTTP interaction.

Example vulnerable flow:
----------------------------------------
1. Visit https://target.com/contact-us/
2. Enter Burp Collaborator payload in URL field.
3. Submit form.
4. Check Burp Collaborator for DNS/HTTP interaction.

----------------------------------------
SSRF via XML-RPC
----------------------------------------
Test by injecting Collaborator URL into any URL parameter in XML-RPC requests.

----------------------------------------
SSRF via Open Redirect
----------------------------------------
Chain SSRF using open redirect endpoints to bypass filters.
